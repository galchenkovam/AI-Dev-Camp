- Tasks are GitHub issues, one at a time.
- Read the task description and acceptance criteria before starting work.
- Read the relevant product context in `_docs/plan.md` before making scope or
  behavior decisions.
- Finish one task before moving to the next issue.
- Commit regularly, especially after a task is completed and verified.
- Keep each issue small enough to finish in a single session and independent
  enough to hand off to another contributor.
Roles

- PM - grooms a task before anyone implements it, follows _docs/team/pm.md
